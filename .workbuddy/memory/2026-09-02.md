### 推演发现的 bug 与修复（js/main.js，v2.1.7→v2.1.8，?v=1416）

1. **sync 旧快照回退局号 + 二次 nextRound（重大）**：sync（state 通道乱序）旧行 `else STATE.roundNum = d.rn` 非单调——回合 R→R+1 刚重置后，在途旧 sync{rn:R, over:true, 旧比分} 落地 → 局号回退+roundOver 翻回+比分闪回；紧接着新 sync{rn:R+1} 因超前又二次触发 nextRound → 开局瞬间实体回出生点。修复：staleSnap（d.rn < roundNum）整段跳过 s0/s1/over/rn，rn 只前进不回退。
2. **nextRound 未开局空引用竞态（崩溃）**：sync 兜底 nextRound(d.rn) 可在 'go'/'map' 到达前触发（state/event 双通道无跨通道顺序），me/myPlane 为 null → TypeError。修复：nextRound 入口 `if (!STATE.started) return`。
3. **选阵营阶段掉线永久死等（重大）**：原广播 pickCancel 回大厅"等待重新连接"，但无重连机制 → 永远卡死。修复：强制完成选阵营（已选保留、未选自动补到人少的队、允许 3v2 不对称）→ completePickAndDeal() 重发 pickList（pickRound 幂等）→ tryStartMatchFromReady()（阈值按掉线后 netSize 重算）立即开局。completePickAndDeal/tryStartMatchFromReady 从 broadcastPickCount/ready handler 抽取共用。
4. **奇数人数选阵营死锁（重大）**：掉线后 netSize=5/7/9，两队容量原同用 floor(netSize/2) → 总容量<人数 → 永远凑不齐，45s 超时强塞后 c1<=ts 仍不满足 → pickPhase 卡死。修复：pickTs → pickTs0/pickTs1（floor/ceil），涉及 startPickPhase/broadcastPickCount/selectPick/updatePickUI/case 'pick'/pickStart/pickCount(消息字段 ts→t0,t1)。
5. **非房主对"对手全部掉线=比赛结束"无感知**：房主端 endMatchIfFoesGone 就地结束但不广播 → 非房主瞪空地图。修复：抽取 endMatchIfFoesGone()（原 onClose 内联逻辑），peerGone 处理器在非房主端对称调用。
6. **非房主大厅 25s 兜底抢跑开局**：选阵营最长 45s，25s 兜底提前 beginMatch → 丢弃 pickList/team（STATE.started 后 pickList 被拒）→ 阵营错乱+地图错乱（3v3 兜底固定 island）。修复：60s + banner"主机长时间未响应"+reload（正常掉线由 onClose 秒级处理）；pickStart 处理器 clearInterval(mapLobbyTimerId)。
7. 上轮遗留确认：matchEnd 视角（v2.1.7 已修，s0/s1 本地换算）、非房主死亡上报 died（v2.1.7）、rEnd 携带 w 回合横幅（v2.1.7）——本轮全流程推演验证闭环。
