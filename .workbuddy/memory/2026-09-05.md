# 术语澄清 + 局号看门狗自愈（9/12 16:10）

## 术语（代码变量 ↔ 中文）
- `STATE.roundNum` = **回合序号**（五局三胜里的"第几局"），房主是唯一权威，递增/回退只由房主决定
- `STATE.s0/s1` = 两队**回合胜场比分**，任意一方到 3（WIN_ROUNDS）→ 整场结束
- `STATE.roundOver` = **当前回合是否已结束**（回合之间的过渡窗口，期间锁操作）
- `STATE.matchEnded` = **整场是否结束**（结算面板、等「再来一局」）
→ 用户口中的"局号"若指回合数，那就是 roundNum；"大对局"= 整场（match）

## 选阵营机制（代码路径）
1. 触发：3v3/5v5 房主选图后调 `startPickPhase()`；防空车玩法（含 1v1）连接后直接进入。
2. 房主：`pickRound++`（表格版本号，幂等）→ 广播 `pickStart{round}` → 每 800ms 广播 `pickCount{c0,c1,t0,t1,round}`（同时 45s 超时自动分配挂机者）。
3. 玩家：点阵营 → `pick{s ide}` 发给房主（房主自己则写入 pickSelections）→ 房主更新人数并广播。
4. 收满（`c0+c1>=netSize` 且各队不超容）→ `completePickAndDeal()`：房主 `applyPickTeams` 落 team/slot → 逐人定向发 `pickList{team,slot,m:[队友],f:[对手],round}`（每人只拿到"我的视角"，无全量名单、无互校链）。
5. 玩家收到 `pickList` → 落 roster → 回 `ready`；房主 `pickReadySet` 收满 `netSize-1` → 广播 `go{map}` → 两端 `beginMatch()`。
6. 掉线：房主重算 netSize 并重发 roster，`tryStartMatchFromReady()` 按新人数立刻开局；取消时广播 `pickCancel`。

# 麦克风瞬态杂音根因 + 选阵营机制三问（9/12 傍晚）

## 麦克风「刚开麦一阵嘈杂、随后消失」根因
- 现象内容：对方听到的是**本机游戏音效**（枪声/引擎）且很嘈杂，1~2 秒后消失
- 根因：**声学回声 + 浏览器 AEC 收敛期**。麦克风以 echoCancellation:true 打开，WebRTC 的回声消除必须先拿"本机正在播放的信号"作为参考来估计回声路径（时延+房间响应），收敛前（约 0.3~1.5s）外放的游戏音被原样传出去；收敛完成后回声被减掉 → 声音消失。手机外放（扬声器功率大）尤其明显；戴耳机则声学回路断开、基本消失
- 修复：新增**预热窗口** `micArmT = now + 600ms`，窗口内 onaudioprocess 直接丢弃、不发包（等 AEC 收敛后再开始传）
- 另：接收端抖动缓冲起步（首包对齐 + 80ms 跳进）也会带来开头几声咔哒，属次级因素
- ?v=1451→1452；帮助文案补「外放时对方会听到游戏音效，建议戴耳机」

## 选阵营机制三问（代码依据）

# 选阵营掉线边界：两个真实漏洞已修（9/12 傍晚，用户提问触发）

用户追问 5v5 分情况的掉线行为 → 复查代码发现两个漏洞：

## 漏洞 1：掉线者的选边记录不清理 → 幽灵玩家
- 旧：removePeerLocal 清 roster/nets/planes/voice，但**不清 pickSelections**。若他在掉线前已选边，
  掉线后重发名单时 `teams` 仍包含他 → `applyPickTeams` 因 roster.find 失败把他**重新 push 回 roster**
  → 所有人视角出现一个占出生位、永不移动的单位；更严重的是 `teamAliveCount` 永远把他算作存活
  → **回合永远无法靠"全灭"结束**（只能等有人撞地/撞海）
- 修：removePeerLocal 增加 `delete pickSelections[peerId]` + `pickReadySet.delete(peerId)`

## 漏洞 2：人数下降后不重平衡容量 → 可能出现 0 人空队
- 场景（用户举例）：10 人时 5 人全选 A（当时容量 5，合法）→ 掉 7 人剩 3 人 → 新容量 floor(3/2)=1 / 2
  → A 队 3 人超额；旧代码只给"未选者"补位，不处理超额 → 发出 A3:B0 名单 → 空队每回合立刻判负（白送回合）
- 修：新增 `rebalancePicks()`（只房主跑）：按新 netSize 重算 pickTs0/pickTs1，把超额一侧的人按
  peerId 排序移到另一侧；因为玩家端队伍完全来自 pickList，改判安全。调用点在"掉线强制完成"分支里，
  位于自动补位之前（先保证各队不超容，再补满 → 最终必然两队都满、无空队）

## 顺带兜底
- 掉线后只剩房主一人（roster.length<=1）：banner「所有玩家已离开」+ 2.5s 后回主菜单（此前会单人开局空对局）

## 行为矩阵（5v5=10 人，容量 5/5）
| 情形 | 行为 |
|---|---|
| 已选边后掉线 | 清其选边+ready → netSize 重算 → 容量重算 → 重平衡 → 未选者补位 → 重发定向名单（同 pickRound，收到方幂等并重发 ready）→ 收满 ready 即开局（允许 4v5 不对称） |
| 未选边就掉线 | 同上；他没有选边记录，自动补位把他之外的人安排 |
| 掉 1 人（9 人） | **不用等 45s 兜底**：掉线即触发强制完成路径，容量变 4/5，立刻补位重发名单开局；45s 超时只针对"无人选边且无人掉线"的挂机场景 |
| 掉 7 人剩 3 人且都选同一队 | 重平衡后变 1v2（A 最多留 1 人）→ 正常开局；修复前会 A3:B0 空队白送回合 |
