### 1v1 联机（工程内 Net.java）
- 传输：**局域网 TCP**（同 WiFi），房主 ServerSocket:45678，加入方填「房主IP:端口」= 房间码
- 报文：`k=v;k=v` 换行分帧文本（`t=s` 状态20Hz / `t=hit` 命中 / `t=rn` 局号 / `t=rEnd` / `t=me`）
- 权威划分：**各自权威自己血量**（命中方发 hit 给被打方）+ **房主独占回合/比分裁决**（沿用网页版修正后的原则）
- 网络安全：网络线程只写 volatile 缓冲，主循环读取后应用（避免跨线程改游戏状态）
- UI：HudView 画「联机」入口与面板；加入房间用原生 AlertDialog + EditText 输入房间码（不引 AndroidX）
- 联机宽限期 0.6s：一方死后等 0.6s，若另一方也死 → **平局**（双方不计分）
- 已知限制：仅局域网；子弹不做跨端同步（命中靠 hit 报文）；无语音；无重赛（需重新建房）

### 网页版"同时死亡"判定（用户提问，已确认）
- `checkRoundEnd`：两队存活都为 0 → 立即 `settleRound('draw')` → 横幅「双方同归于尽」+「平局 · 双方均不计分」，**双方都不加分**，3.2s 后照常进入下一回合
- 关键：**0.8s 淘汰宽限期**（`teamElimTimer`）—— 先死的一方不会立刻判负，留给另一方 0.8s 内"追上"死亡，从而判平局；超过 0.8s 才算先死者输
- 同时撞海/撞地同理（环境死亡也走 selfDestruct → checkRoundEnd）

  · **房主模拟双方子弹**：加入方点开火只上报弹道（`t=fire;ox..dz..`），房主 `spawnPeerBullet` 生成并权威判伤

  · **环境伤害/坠毁上报**：加入方撞地/出界 → `t=dmg`；坠毁 → `t=died`，均由房主扣血

- 位置仍由各自上报（LAN 延迟极低，暂不做预测/回溯），与网页版的"本地仿真+权威快照"差异已在 README 表格标明

## 追加（同日夜）：JSON 协议对齐（跨端互通基础）

- Net.java 的报文格式从 `k=v;k=v` 改为 **JSON**（`JSONObject`/`JSONArray`），字段名与网页版完全一致
- 报文类型：upd(20Hz位姿) / sync(权威快照) / fire(开火上报) / blt(曳光广播) / fx(命中表现) / rEnd / round / me / died / dmg / died / hello / peerGone / go
- upd 格式：飞机 `{t:"upd", p:[x,y,z], q:[qw,qx,qy,qz], sp:N}`；防空车 `{t:"upd", p:[x,y,z], ty:..., tp:..., by:..., sp:N}`
- sync 格式：`{t:"sync", lst:[{id, p:[..], q:[..], hp, al}, ...], s0, s1, rn, over}`
- fire 格式：`{t:"fire", o:[..], d:[..], fid, s, dm, sl}`
- 坐标系：四元数 (w,x,y,z) 顺序与 three.js 一致；Y-up，-Z 前方
- dispatch 方法重写：JSONObject 解析替代 k=v 解析；S 通道只处理 upd/sync；E 通道处理事件
- **跨端互通的关键前提已满足**：SDP 编码一致 + JSON 报文字段一致 + 坐标系一致
