⇄两条通道：谁可靠、谁实时

通道创建方式承载语义后果
s 状态 createDataChannel('s', {ordered:false, maxRetransmits:0}) upd（上报位姿 20Hz）、sync（房主快照 20Hz）、voice（语音帧） 丢了就等下一个。位姿用 lerp 平滑，画面约滞后 1 RTT；语音有 80ms 重排窗，缺包跳过不阻塞。
e 事件 createDataChannel('e')（默认参数） hello / team / roster / fire / blt / fireRocket / rkt / hitRep / hit / hitReject / kill / kstat / died / crash / envDmg / round / rEnd / matchEnd / pickList / go / ping / pong / kick / modeMismatch 可靠有序：不会丢，但一个包丢了后面全排队等重传（队头阻塞 → 几十到几百 ms 的延迟尖峰）。

子弹与命中全部走 e，所以「hitRep 丢包」在网络层不会发生；会失效的只有逻辑丢弃（回合已结束、目标已死、去重表命中）和 40m 位置校验拒绝。 反过来，位姿走 s，所以「开火快照」与「对方看到的机体位置」天然对不齐。

⚠掉线、延迟门槛与模式一致性

  • 1
    延迟门槛：连接建立后立刻采样 3 次 RTT（取最小值，首包受 ICE 影响偏大），≥ 80ms 直接 kick 并延迟重载页面。通过检测才算「就绪」，人齐判定用的是就绪人数 —— 所以不合格的玩家会在进入选图/选阵营之前被剔除，不会把房主从选人界面打回大厅；主动踢出也不缩编（3v3 不会悄悄变成 2v2）。
  • 2
    掉线：onClose → 删除连接与 roster 条目 → 该玩家按阵亡结算；回合内剩余玩家继续，房主推进 rEnd。
  • 3
    模式一致性（v3.11）：邀请码里带房主的 gm，加入方在生成应答码前就比对；不一致直接拒绝，连 PeerConnection 都不建。连接后 hello 再带一次 gm 兜底（兼容旧版客户端），不一致由房主踢出并提示双方模式名。
  • 4
    回合推进：round 走可靠通道正常先到；丢了由 sync 的 rn 超前兜底。rn 落后的旧快照整段跳过，防局号回退与二次重置。
  • 5
    回菜单是就地软重置（v3.11.2）：返回 / 被踢 / 掉线 / 超时都不再 location.reload()，而是按「停输入 → 关连接 → 清实体 → 清状态 → 清 UI → 重建菜单 3D」复位。连接关闭走 Net.close()（先 DataChannel 后 PeerConnection），对端通过 onClose 各自软重置。

◎已知边界（设计取舍，不是 bug）

  • 1
    视觉弹道不判伤：foeVis 子弹不与飞机/防空车碰撞。命中特效出现前，它已经从目标身上穿过去了 —— 移除时机是 hit 到达的那一帧（killBulletFx 按「射手 + fid」精确匹配）。
  • 2
    跨通道没有顺序保证：hit（e 通道）可能先于一条更早生成的 sync（s 通道）到达，旧快照会把血量短暂覆盖回去（约 50~150ms），随后被下一个快照纠正。
  • 3
    特效位置 ≠ 本地弹道位置：命中特效放在开火者上报的命中点 p，接收端的子弹按自己的积分位置渲染。延迟 100ms、弹速 600 m/s 就是 60m 的视觉差。
  • 4
    40m 是防作弊阈值：按「最大 170 m/s × 80ms + 插值滞后」推出来的容差，用来挡错目标/瞬移/改包，不是精确几何校验。
  • 5
    炸弹 AOE 逐目标上报：一次爆炸命中 N 个目标就发 N 条 hitRep，房主按 rid:fid:id 分别去重结算，互不压制。
